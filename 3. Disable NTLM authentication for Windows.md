
# Disable NTLM Authentication for Windows

## Microsoft Security Recommendation

Microsoft Defender recommends disabling NTLM authentication to reduce identity‑based attack surface and prevent common lateral‑movement techniques such as **Pass‑the‑Hash** and **NTLM relay attacks**.

This document explains:
- What NTLM is and how it works
- Why Microsoft flags it even when no NTLM events are observed
- How to detect NTLM usage safely
- A **phased, real‑world implementation plan** for Domain Controllers, servers, and endpoints

---

## 1. What Is NTLM?

**NTLM (NT LAN Manager)** is a legacy Windows authentication protocol that relies on **password‑derived hashes** rather than modern ticket‑based authentication.

NTLM is used when:
- Kerberos cannot be negotiated
- A system is not domain‑aware
- Legacy applications or devices authenticate
- Authentication falls back due to misconfiguration

> NTLM is not broken cryptographically, but it is **insecure by design for modern enterprise environments**.

---

## 2. How NTLM Authentication Works (Real‑Time Flow)

Below is a **real NTLMv2 authentication flow** when a user accesses a file server.

### Scenario
User `HAREESH` accesses a file share on `FILESRV01`.

---

### NTLM Authentication Flow Diagram

```

+-------------+                 +-------------+                 +------------------+
\|   Client    |                 |   Server    |                 | Domain Controller|
\| (Endpoint)  |                 | (FILESRV01) |                 |       (DC)       |
+-------------+                 +-------------+                 +------------------+
\|                                   |                                   |
\| 1. Access request (no Kerberos)  |                                   |
\|--------------------------------->|                                   |
\|                                   |                                   |
\|                                   | 2. NTLM Challenge                 |
\|                                   |<----------------------------------|
\|                                   |                                   |
\| 3. Response = H(password + nonce)|                                   |
\|--------------------------------->|                                   |
\|                                   |                                   |
\|                                   | 4. Validate NTLM response          |
\|                                   |---------------------------------->|
\|                                   |                                   |
\|                                   | 5. Success / Failure               |
\|                                   |<----------------------------------|
\|                                   |                                   |

```

---

### Key Points
- The **password is never sent**, but the **NTLM hash is reusable**
- If an attacker steals the hash, they can authenticate **without knowing the password**
- No mutual authentication → susceptible to relay attacks

---

## 3. NTLM vs Kerberos (Why NTLM Is Risky)

| Feature | NTLM | Kerberos |
|------|------|---------|
| Authentication method | Hash‑based | Ticket‑based |
| Mutual authentication | ❌ No | ✅ Yes |
| Replay protection | Weak | Strong |
| Pass‑the‑Hash risk | ✅ Yes | ❌ No |
| Modern security support | ❌ No | ✅ Yes |

---

## 4. Why Microsoft Defender Flags NTLM Without Seeing Events

Microsoft Defender’s NTLM recommendation is **configuration‑based**, not purely event‑based.

Defender flags systems as *impacted* when:
- NTLM is allowed by policy
- No NTLM restrictions are enforced via GPO
- Systems **would accept NTLM if negotiated**

> Absence of NTLM logs implies good Kerberos hygiene, **not absence of risk**.

## 5. Where NTLM Typically Appears in Real Environments

| Category | Common Examples |
|-------|----------------|
| Domain Controllers | Legacy trusts, old clients |
| Member Servers | Misconfigured SPNs, services |
| Endpoints | Legacy scripts, SMB access |
| Printers | Scan‑to‑folder, scan‑to‑mail |
| Linux / NAS | Old Samba, NTLM SMB mounts |
| Service Accounts | Legacy applications |

## 6. Detecting NTLM Authentication

### 6.1 Enable NTLM Auditing (Mandatory First Step)

Enable audit‑only mode to gain visibility **without breaking anything**.

**Group Policy Path (Domain Level):**
```

Computer Configuration →
Windows Settings →
Security Settings →
Local Policies →
Security Options

```

Set:
```

Network security: Restrict NTLM: NTLM authentication in this domain
→ Audit all

```

---

### 6.2 Where NTLM Audit Events Appear

**Domain Controllers only:**
```

Applications and Services Logs →
Microsoft →
Windows →
NTLM →
Operational

```

| Event ID | Meaning |
|--------|--------|
| 8001 | NTLM authentication attempted |
| 8002 | NTLM blocked |
| 8004 | Outgoing NTLM blocked |

---

### 6.3 Security Log Correlation (Fallback)

Look for:
- Event ID `4624` / `4625`
- `Authentication Package: NTLM`
- `Logon Process: NtLmSsp`
- Logon Types: `3` (Network), `5` (Service)

---

## 7. Phased Implementation Strategy (Strongly Recommended)

❗ **Never disable NTLM in one step in production**

---

### Phase 0 – Audit Only
- Enable NTLM auditing
- Observe for 1–2 weeks

---

### Phase 1 – Harden Without Blocking
```

Network Security: LAN Manager Authentication Level
→ Send NTLMv2 response only / refuse LM & NTLM

```

Safe for all systems.

---

### Phase 2 – Block NTLM on Workstations
- Incoming NTLM: Deny all
- Outgoing NTLM: Deny all

Lowest business impact.

---

### Phase 3 – Block NTLM on Member Servers
- Fix application dependencies
- Correct SPNs
- Replace legacy auth

---

### Phase 4 – Block NTLM Domain‑Wide (DCs)
⚠️ **Final step only**
```

Network Security: Restrict NTLM: NTLM authentication in this domain
→ Deny all accounts

```

---

## 8. Final Enforcement Configuration (Target State)

### Group Policy Settings

```

Network Security: LAN Manager Authentication Level
→ Send NTLMv2 response only / refuse LM & NTLM

Network Security: Restrict NTLM: Incoming NTLM Traffic
→ Deny all accounts

Network Security: Restrict NTLM: Outgoing NTLM Traffic to remote servers
→ Deny all accounts

Network Security: Restrict NTLM: NTLM authentication in this domain
→ Deny all accounts (Domain Controllers only)

```

Run:
```

gpupdate /force

````

---


```reg
HKLM\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0
RestrictReceivingNTLMTraffic = 2
RestrictSendingNTLMTraffic = 2
```

```reg
HKLM\SYSTEM\CurrentControlSet\Services\Netlogon\Parameters
RestrictNTLMInDomain = 7
```

🔁 Reboot required.

***

## 10. Validation After Enforcement

✅ NTLM Operational Log should show:

*   No new Event ID 8001
*   Only blocked attempts (8002/8004)

✅ Microsoft Defender recommendation should move to **resolved**

***

## 11. Key Takeaway

> Disabling NTLM removes a legacy, reusable‑credential authentication protocol and replaces it with secure, ticket‑based authentication, significantly reducing credential theft and lateral movement risk.
