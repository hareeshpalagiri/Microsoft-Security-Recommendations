# Security Recommendation Report

## Enable **Local Security Authority (LSA) Protection**

***

## 1. Executive Summary

**Local Security Authority (LSA) Protection** is a Windows security hardening feature designed to protect the **Local Security Authority Subsystem Service (LSASS)** from credential theft, memory tampering, and code injection attacks. LSASS is a critical Windows process responsible for handling authentication, authorization, and credential management.

Microsoft recommends enabling LSA Protection on all supported **Domain Controllers, servers, and user devices** to significantly reduce the risk of credential dumping attacks such as Pass-the-Hash and Pass-the-Ticket.

This report explains what LSA and LSASS are, why the recommendation exists, how it improves security, potential impact, required checks, remediation steps, and verification procedures.

***

## 2. What is LSASS and LSA?

### Local Security Authority (LSA)

LSA is a core Windows security component responsible for:

*   Enforcing security policies
*   Managing authentication packages (Kerberos, NTLM)
*   Creating access tokens
*   Handling logon sessions

### LSASS (Local Security Authority Subsystem Service)

*   Executable: `lsass.exe`
*   Location: `C:\Windows\System32\lsass.exe`
*   Runs on **every Windows system**
*   If LSASS stops → the system crashes

LSASS is the **process** through which LSA operates.

***

## 3. What data does LSASS handle?

When a user logs into a Windows system, LSASS manages and maintains sensitive authentication data in memory.

### Stored or managed by LSASS (in memory):

*   NTLM password hashes (when NTLM is used or cached)
*   Kerberos **Ticket Granting Tickets (TGTs)**
*   Kerberos **service tickets (TGS)**
*   Session keys
*   Logon session metadata

> ⚠️ Plain‑text passwords are not normally stored, but **hashes and tickets are sufficient** for attackers.

***

## 4. Why LSASS is a high‑value attack target

Attackers frequently attempt to dump LSASS memory to extract credentials using tools such as:

*   Mimikatz
*   Procdump
*   Task Manager (older Windows versions)
*   Custom malware

A successful LSASS dump can enable:

*   Pass‑the‑Hash
*   Pass‑the‑Ticket
*   Lateral movement
*   Privilege escalation
*   Full domain compromise (especially on Domain Controllers)

***

## 5. What is LSA Protection?

**LSA Protection** forces LSASS to run as a **Protected Process Light (PPL)**.

### What this means:

*   Only Microsoft‑signed, trusted code can interact with LSASS
*   Even local administrators or SYSTEM processes cannot read LSASS memory
*   Unauthorized memory access and code injection attempts are blocked

### Security outcome:

✅ Credential dumping attacks fail  
✅ LSASS memory is protected  
✅ Attack surface is significantly reduced

***

## 6. Why Microsoft recommends enabling LSA Protection

LSA Protection directly mitigates one of the **most common post‑exploitation techniques** used in Windows attacks.

### Key benefits:

*   Protects credentials in memory
*   Prevents credential theft without user impact
*   Improves Microsoft Secure Score
*   Aligns with Zero Trust and identity hardening practices
*   Complements Defender for Identity and Defender for Endpoint

***

## 7. Scope: Where should LSA Protection be enabled?

### Target state (recommended):

| Asset Type                                            | Recommendation         |
| ----------------------------------------------------- | ---------------------- |
| **Domain Controllers**                                | ✅ Mandatory            |
| **Tier‑0 / Identity servers (AD Connect, ADFS, PKI)** | ✅ Strongly recommended |
| **All other servers**                                 | ✅ Recommended          |
| **User workstations (Windows 10/11)**                 | ✅ Recommended          |
| Unsupported / legacy OS                               | ❌ Not supported        |

Priority order:
**Domain Controllers → Tier‑0 servers → Other servers → User devices**

***

## 8. Impact Assessment

### Positive Security Impact

*   Blocks credential dumping tools
*   Reduces lateral movement risk
*   Protects high‑privilege account credentials
*   No change to authentication workflows

### Potential Operational Impact

*   Legacy or unsupported security/credential software may fail
*   Old, unsigned drivers interacting with LSASS may be blocked

Modern Microsoft Defender, Defender for Identity, and supported EDR solutions are compatible.

***

## 9. Pre‑Remediation Checks

Before enabling LSA Protection:

### ✅ Check current status

```powershell
Get-ItemProperty HKLM:\SYSTEM\CurrentControlSet\Control\Lsa | 
Select RunAsPPL, RunAsPPLBoot
```

### ✅ Validate OS support

*   Windows 10 (1903+)
*   Windows 11
*   Windows Server 2016+
*   Windows Server 2019 / 2022 (recommended for DCs)

### ✅ Confirm security tool compatibility

*   Antivirus / EDR
*   Backup agents
*   Credential providers

***

## 10. Remediation Methods

### Method 1: Group Policy (Recommended for DCs & Servers)

**Policy Path**

    Computer Configuration
    └─ Administrative Templates
       └─ System
          └─ Local Security Authority

**Setting**

*   Configure LSASS to run as a protected process
*   Set to: **Enabled**
*   Option: **Enabled with UEFI Lock**

Link:

*   DC GPO → Domain Controllers OU
*   Server GPO → Servers OU

✅ Requires reboot

***

### Method 2: Registry (Manual or scripted)

```powershell
New-ItemProperty `
 -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" `
 -Name "RunAsPPLBoot" `
 -PropertyType DWord `
 -Value 2 `
 -Force
```

✅ Requires reboot

***

### Method 3: Intune (User devices)

*   Device Configuration Profile
*   Settings Catalog or PowerShell script
*   For Windows 10/11 Entra or Hybrid joined devices

***

## 11. Verification Steps

### Registry verification

```powershell
Get-ItemProperty HKLM:\SYSTEM\CurrentControlSet\Control\Lsa
```

Expected result:

*   `RunAsPPLBoot = 2`

***

### Event Viewer

    Applications and Services Logs
    └─ Microsoft
       └─ Windows
          └─ LSA

Look for confirmation that LSASS started in protected mode.

***

### Defender Portal

*   Recommendation status: **Resolved**
*   Device security → LSA Protection enabled

***

## 12. Rollback Plan

If unexpected issues occur:

```powershell
Remove-ItemProperty `
 -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" `
 -Name RunAsPPL, RunAsPPLBoot
```

Reboot the system to restore previous behavior.

***

## 13. Conclusion

Enabling **Local Security Authority (LSA) Protection** is a **high‑value, low‑risk security hardening measure**. It protects one of the most critical Windows security processes—LSASS—against credential theft and post‑exploitation attacks.

Microsoft strongly recommends enabling this control across all supported Windows systems, with **Domain Controllers as the highest priority**. When deployed using Group Policy or Intune and validated through Microsoft Defender, LSA Protection significantly strengthens enterprise identity security without impacting normal operations.
